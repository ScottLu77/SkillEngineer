# Rule 1 - 工作情境決定骨架來源與預設展開模式

- 目標 skill 目錄不存在時，必須判定為建立。
- 目標 `SKILL.md` 已有 `# SOP` section 時，必須判定為優化。
- 目標 skill 已存在但 `SKILL.md` 沒有 `# SOP` section 時，必須判定為遷移。
- 骨架來源與預設展開模式必須依下表決定。
- 優化與遷移不得增加、刪減或放寬既有內容的要求；使用者另外要求原本沒有的內容時，該內容必須使用新增模式。
- 素材來自 SOP 步驟內文以外的既有檔案時，必須使用新增模式，並以該檔案作為素材。
- 建立情境的 SOP 大綱不得將準備展開的判準、格式或命令寫入步驟摘要；這些內容必須列為部位分派表的素材。

| 工作情境 | 骨架來源 | 預設展開模式 |
| -------- | -------- | ------------ |
| 建立 | 依使用者需求寫出新的 SOP | 新增 |
| 優化 | 既有 SOP，只修正不符合 SOP 規範之處 | 抽取 |
| 遷移 | 將既有 `SKILL.md` 內文轉寫為 SOP | 抽取 |

## Example

- 每列都能由目標 skill 的現況判斷情境；最後一列的格式說明位於 SOP 以外的檔案，因此使用新增模式。

| 目標 skill 現況 | 使用者需求 | 工作情境 | 展開模式 |
| --------------- | ---------- | -------- | -------- |
| 目錄不存在 | 做一個產生會議紀錄的 skill | 建立 | 新增 |
| `SKILL.md` 有 `# SOP`，步驟內文夾帶判準 | 幫我整理這個 skill | 優化 | 抽取 |
| `SKILL.md` 有 `# SOP` | 整理之外，待辦事項還要加上期限 | 優化 | 既有內容抽取；期限要求新增 |
| `SKILL.md` 是散文，格式說明放在 `references/format.md` | 改成模組化格式 | 遷移 | 散文中的判準抽取；`references/format.md` 的格式新增 |

# Rule 2 - 步驟內容必須依性質分類

- SOP 大綱中每個步驟要承載的內容，必須依下表分類為四種性質之一。
- 一個步驟含有多種性質時，每種性質必須各自成為一個候選。
- 性質為控制的內容必須留在步驟內文，不得成為候選。
- 本 Rule 的分類只用來決定委派對象；候選是否適用，由被委派的 skill 依其自身的規則判定。

| 性質 | 內容 | 委派對象 |
| ---- | ---- | -------- |
| 判準 | 用來判斷產出是否合格的要求 | `skill-derive-rule` |
| 格式 | 產出物的結構、區塊順序與固定字面值 | `skill-derive-template` |
| 機械 | 相同輸入只有一種正確結果、不需要理解語意的操作 | `skill-derive-script` |
| 控制 | 執行條件、分支、停止點、要完成的決策或產物 | 無，留在步驟內文 |

## Example

- 第一列同時含有格式與判準，拆成兩個候選；最後一列只有執行條件與分支，沒有候選。

| 步驟要承載的內容 | 候選 |
| ---------------- | ---- |
| 產生會議紀錄，依序列出決議與待辦事項，每項決議必須寫出結論 | 格式：決議與待辦事項的段落順序；判準：每項決議必須寫出結論 |
| 列出會議紀錄中負責人欄位為空的待辦事項 | 機械：逐列比對欄位 |
| 逐字稿超過一場會議時，向使用者確認要處理哪一場 | 無：只有執行條件與分支 |

# Rule 3 - 候選必須通過價值門檻才展開

- 候選符合下表任一項門檻時，必須列入部位分派表。
- 候選不符合任何門檻時，不得列入部位分派表，並必須列入工程藍圖的「不展開的內容」與原因。
- 使用者明確要求展開或不展開某個候選時，必須依使用者要求，並在理由中註明。
- 部位分派表可以沒有任何列。

| 性質 | 門檻 |
| ---- | ---- |
| 判準 | 同一步驟有兩項以上判準；或同一組判準被兩個以上步驟使用 |
| 格式 | 產出物有兩個以上固定區塊；或產出物會被其他工具或步驟依固定結構讀取 |
| 機械 | 操作含有兩個以上命令或逐項比對；或同一操作被兩個以上步驟使用 |

## Example

- 前三列各自符合一項門檻；後兩列只有單一判準與單一讀取，留在步驟內文。

| 候選 | 判定 | 原因 |
| ---- | ---- | ---- |
| 決議必須寫出結論；待辦事項必須有單一負責人 | 展開 | 同一步驟有兩項判準 |
| 會議紀錄依序包含與會者、決議、待辦事項 | 展開 | 有三個固定區塊 |
| 逐列找出負責人或期限為空的待辦事項 | 展開 | 逐項比對 |
| 只整理逐字稿中明確說出的決議 | 不展開 | 只有一項判準，且只有一個步驟使用 |
| 讀取逐字稿檔案 | 不展開 | 單一讀取，不是逐項比對 |

# Rule 4 - 部位分派表必須依固定順序排列

- 部位分派表必須依目標步驟的位置由後往前排列：Phase 編號大的在前，同一個 Phase 內步驟編號大的在前。
- 同一個目標步驟有多列時，必須依 `skill-derive-script`、`skill-derive-template`、`skill-derive-rule` 的順序排列。
- 每一列處理完成後，必須更新尚未處理的列中受重新編號影響的目標步驟。

## Example

- Phase 2 步驟 2 排在步驟 1 之前，使步驟 2 展開後插入的步驟不影響步驟 1 的編號；步驟 1 的兩列先樣板後規則。

| 順序 | 目標步驟 | 委派對象 |
| ---- | -------- | -------- |
| 1 | Phase 2 步驟 2 | `skill-derive-script` |
| 2 | Phase 2 步驟 1 | `skill-derive-template` |
| 3 | Phase 2 步驟 1 | `skill-derive-rule` |

# Rule 5 - 每一列必須備齊委派所需的資訊

- 部位分派表的每一列必須包含下表所有欄位。
- 抽取模式的素材必須引用目標步驟或既有內文中要被抽取的原文。
- 新增模式的素材必須依委派對象提供：`skill-derive-rule` 提供要求清單；`skill-derive-template` 提供區塊組成或產出物樣本；`skill-derive-script` 提供輸入來源與預期輸出。
- 素材不足時，不得自行擬定；必須在素材欄標示「待補」與需要使用者提供的資訊。

| 欄位 | 內容 |
| ---- | ---- |
| 順序 | 從 `1` 開始的執行順序 |
| 目標步驟 | Phase 編號與步驟編號 |
| 性質 | 判準、格式或機械 |
| 委派對象 | 對應的 `skill-derive-*` |
| 展開模式 | 抽取或新增 |
| 素材 | 被抽取的原文，或新增所需的資訊 |
| 理由 | 符合的價值門檻，或使用者的要求 |

## Example

- 第一列的新增素材提供了輸入來源與預期輸出；第二列缺少區塊組成，標示待補而不自行擬定。

| 順序 | 目標步驟 | 性質 | 委派對象 | 展開模式 | 素材 | 理由 |
| ---- | -------- | ---- | -------- | -------- | ---- | ---- |
| 1 | Phase 2 步驟 2 | 機械 | `skill-derive-script` | 新增 | 輸入：會議紀錄檔路徑；輸出：負責人或期限為空的待辦事項，每行一項 | 逐項比對 |
| 2 | Phase 2 步驟 1 | 格式 | `skill-derive-template` | 新增 | 待補：會議紀錄的區塊組成，或一份過去的會議紀錄 | 使用者要求固定格式 |

# Rule 6 - 部位內容必須委派，不得由本 skill 撰寫

- 目標 skill 的每一項寫入工作必須由下表的負責者完成。
- 工程藍圖不得包含 RuleFile、樣板組或 ScriptFile 的內容草稿；內容草稿由被委派的 skill 在其展開方案中提出。
- 被委派的 skill 判定候選不適用，或使用者在其展開方案階段放棄時，必須將該列記錄為未展開與原因，並繼續處理下一列。

| 寫入工作 | 負責者 |
| -------- | ------ |
| `SKILL.md` 的 `# SOP` section | `skill-form-sop` |
| 為步驟展開部位並更新接線 | 該列指定的 `skill-derive-*` |
| 修正既有部位內容且不改接線 | 對應的 `skill-form-*` |
| 目錄、frontmatter、既有檔案的搬移與刪除 | 本 skill |

## Example

- 工程藍圖只交代素材與理由；Rule 的標題與條列說明留給 `skill-derive-rule` 的展開方案。

| 工程藍圖的素材欄 | 判定 |
| ---------------- | ---- |
| 要求清單：決議必須寫出結論；待辦事項必須有單一負責人 | 符合：只提供素材 |
| `# Rule 1 - 決議必須寫出結論`，附完整條列說明與 Example | 不符合：這是 RuleFile 的內容草稿 |
