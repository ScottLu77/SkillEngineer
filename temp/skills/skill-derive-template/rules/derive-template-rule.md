# Rule 1 - 目標步驟與適用性必須明確

- 目標步驟必須以 Phase 編號與步驟編號唯一指定。
- 目標步驟要規範的是產出物的結構或格式時，必須判定為適用樣板組。
- 目標步驟不產生產出物時，必須判定為不適用樣板組。
- 目標步驟要規範的只有判斷內容是否合格的判準時，必須判定為不適用樣板組，並建議使用者改用 `skill-derive-rule`。
- 目標步驟同時含有格式與判準時，必須只展開格式，並在展開方案中列出未展開的判準與改用 `skill-derive-rule` 的建議。
- 展開方案不得將判準寫入樣板組；樣板組與 RuleFile 的分工參見 `skill-form-template` 的 `rules/TemplateFile-rule.md` Rule 7。

## Example

- 每列都能由目標步驟的現況判斷是否適用；混合的步驟只展開格式，判準留給 `skill-derive-rule`。

| 目標步驟內文 | 適用性 |
| ------------ | ------ |
| `WRITE` 產生 release note，以版本號為標題，依序列出「新增」與「修正」兩個段落。 | 適用：規範的是產出物的結構 |
| `WRITE` 產生 release note，每項變更必須說明使用者可見的變化。 | 不適用：只有判準，建議改用 `skill-derive-rule` |
| `WRITE` 產生 release note，以版本號為標題，每項變更必須說明使用者可見的變化。 | 適用：只展開標題格式；「說明使用者可見的變化」列為未展開的判準 |
| `THINK` 判斷本次發佈是否包含破壞性變更。 | 不適用：不產生產出物 |

# Rule 2 - 展開模式必須明確

- 目標步驟內文含有產出物的結構或格式描述時，必須使用抽取模式。
- 使用者要求為目標步驟補上原本沒有的樣板時，必須使用新增模式。
- 同一個目標步驟同時符合兩種模式時，展開方案必須同時包含兩種模式，並標明骨架每個區塊的來源模式。
- 新增模式中，使用者沒有提供產出物的區塊組成或產出物樣本時，必須將其列為缺少的資訊。

## Example

- 每列都能由目標步驟內文與使用者需求判斷模式；新增模式缺少區塊組成時列為缺少的資訊。

| 目標步驟內文 | 使用者需求 | 展開模式 |
| ------------ | ---------- | -------- |
| `WRITE` 產生 release note，以版本號為標題，依序列出「新增」與「修正」兩個段落。 | 把這一步的格式抽成樣板 | 抽取 |
| `WRITE` 產生 release note。 | 幫這一步加上樣板，附上一份過去的 release note | 新增 |
| `WRITE` 產生 release note，以版本號為標題。 | 另外加上「已知問題」段落 | 抽取與新增 |
| `WRITE` 產生 release note。 | 幫這一步加上樣板 | 新增；區塊組成列為缺少的資訊 |

# Rule 3 - 抽取必須保留原有格式語意

- 目標步驟中每一項被抽取的格式描述，必須對應到骨架的固定內容、placeholder 或指示註解。
- 抽取不得新增原步驟沒有的格式要求，也不得刪減或放寬原有格式要求。
- 原步驟沒有指定、但骨架必須決定的字面值，必須在展開方案中標示為補定內容。
- 使用者提供產出物樣本或目標 skill 已有既有產出物時，範例的情境必須取自該內容。
- 沒有可取用的內容時，範例的情境可以自行擬定。
- 自行擬定範例的情境時，必須在展開方案中標示為擬定內容。
- 抽取後，目標步驟必須改為依載入結果名稱執行，不得殘留已抽取的格式描述。

## Example

- 原步驟的三項格式描述各自對應到骨架；條列符號 `-` 是原步驟沒有指定的補定內容；改寫後步驟只引用樣板組。

改寫前：

```markdown
3. `WRITE` 產生 release note，以版本號為標題，依序列出「新增」與「修正」兩個段落，每個段落以條列呈現。
```

骨架 `templates/release-note.md`：

```markdown
# {{VERSION}}

## 新增

<!-- 樣板指示：每項新增功能重複一列。 -->
- {{ADDED_ITEM}}

## 修正

<!-- 樣板指示：每項修正重複一列。 -->
- {{FIXED_ITEM}}
```

範例 `templates/release-note.example.md`（擬定內容）：

```markdown
# v2.3.0

## 新增

- 支援以 CSV 匯出請假紀錄。
- 主管審核頁新增批次核准。

## 修正

- 修正跨年度請假天數計算錯誤。
- 修正退回申請後通知信重複寄送。
```

改寫後：

```markdown
3. `READ` `templates/release-note.md` 與 `templates/release-note.example.md`，建立 release note 樣板組。
4. `WRITE` 依已載入的 release note 樣板組，複製骨架並改寫 placeholder，產生 release note。
```

# Rule 4 - 樣板必須歸屬到單一產出物的樣板組

- 目標 skill 的既有樣板組規範的是同一種產出物時，必須修改該樣板組，不得新建重複的樣板組。
- 既有樣板組已涵蓋被抽取的全部格式描述時，展開方案必須標明樣板組內容不變，只更新載入步驟與目標步驟內文。
- 沒有規範同一種產出物的既有樣板組時，必須新建樣板組。
- 目標步驟產生多種產出物時，展開方案必須為每種產出物各自列出樣板組。
- 目標樣板組已由目標步驟所在 Phase 中、位於目標步驟之前的 `READ` 步驟載入時，必須沿用該載入結果名稱，不得新增重複的載入步驟。

## Example

- 「已知問題」段落屬於既有 release note 樣板組的產出物而修改該樣板組；升級指南是另一種產出物而新建。

| 要展開的格式 | 既有樣板組 | 歸屬 |
| ------------ | ---------- | ---- |
| Release note 增加「已知問題」段落 | `templates/release-note.md`、`templates/release-note.example.md` | 修改既有樣板組 |
| 升級指南的章節結構 | 無同產出物的樣板組 | 新建 `templates/upgrade-guide.md`、`templates/upgrade-guide.example.md` |

# Rule 5 - 載入步驟必須同時提名骨架與範例

- 新增或更新的 `READ` 載入步驟，必須在同一個步驟列出骨架與範例兩個檔案的路徑。
- 目標 `SKILL.md` 的既有載入步驟只列出骨架或範例其中一個路徑時，必須補上缺少的路徑。
- 載入結果名稱必須使用「<產出物>樣板組」。
- 改寫後的目標步驟必須以載入結果名稱引用樣板組。
- 載入步驟的位置依 `skill-form-sop` 的 `rules/reference-rule.md` Rule 1。

## Example

- 既有載入步驟只列出骨架，更新後補上範例路徑；載入結果以產出物命名，寫入步驟只引用該名稱。

更新前：

```markdown
2. `READ` `templates/class-diagram.mmd`，建立類別圖樣板。
3. `WRITE` 依已載入的類別圖樣板產生類別圖。
```

更新後：

```markdown
2. `READ` `templates/class-diagram.mmd` 與 `templates/class-diagram.example.mmd`，建立類別圖樣板組。
3. `WRITE` 依已載入的類別圖樣板組，複製骨架並改寫 placeholder，產生類別圖。
```

# Rule 6 - 展開方案必須完整列出變更

- 展開方案必須包含下表所有欄位，供使用者在寫入前確認。
- 抽取模式的展開方案必須列出原步驟格式描述與骨架的對照。
- 展開方案不得包含目標樣板組與目標 `SKILL.md` 以外的檔案變更。

| 欄位 | 內容 |
| ---- | ---- |
| 目標步驟 | Phase 編號、步驟編號與原步驟內文 |
| 展開模式 | 抽取、新增，或兩者 |
| 目標樣板組 | 骨架與範例的檔案路徑，並標明修改、新建或內容不變 |
| 骨架草稿 | 骨架的完整內容，並標明補定內容 |
| 範例草稿 | 範例的完整內容，並標明情境來源或擬定內容 |
| Placeholder 清單 | 定界符，以及每個 placeholder 的名稱與要填入的內容 |
| 載入步驟 | 新增或更新的 `READ` 步驟位置、骨架與範例的路徑、載入結果名稱，或沿用的既有載入結果名稱 |
| 改寫後步驟 | 目標步驟改寫後的內文；新增模式且內文不變時標明不變 |
| 未展開的判準 | 目標步驟中屬於判準的內容與改用 `skill-derive-rule` 的建議；沒有時標明無 |

## Example

- 方案逐欄列出變更，並附上抽取對照，使用者可以直接核對；骨架草稿與範例草稿的內容同 Rule 3 的 Example。

展開方案：

- 目標步驟：Phase 2 步驟 3，`WRITE` 產生 release note，以版本號為標題，依序列出「新增」與「修正」兩個段落，每個段落以條列呈現。
- 展開模式：抽取。
- 目標樣板組：`templates/release-note.md`、`templates/release-note.example.md`（新建）。
- 骨架草稿：完整內容；補定內容為條列符號 `-`。
- 範例草稿：完整內容；情境為擬定內容（請假系統 v2.3.0 發佈）。
- Placeholder 清單：定界符 `{{NAME}}`。

  | 名稱 | 要填入的內容 |
  | ---- | ------------ |
  | `{{VERSION}}` | 本次發佈的版本號 |
  | `{{ADDED_ITEM}}` | 一項新增功能 |
  | `{{FIXED_ITEM}}` | 一項修正 |

- 載入步驟：在 Phase 2 步驟 3 之前新增 `READ` 步驟，列出 `templates/release-note.md` 與 `templates/release-note.example.md`，建立 release note 樣板組。
- 改寫後步驟：`WRITE` 依已載入的 release note 樣板組，複製骨架並改寫 placeholder，產生 release note。
- 未展開的判準：無。

抽取對照：

| 原步驟格式描述 | 骨架對應 |
| -------------- | -------- |
| 以版本號為標題 | `# {{VERSION}}` |
| 依序列出「新增」與「修正」兩個段落 | 固定內容 `## 新增`、`## 修正` 與其順序 |
| 每個段落以條列呈現 | 重複區塊 `- {{ADDED_ITEM}}`、`- {{FIXED_ITEM}}` 與其指示註解 |
