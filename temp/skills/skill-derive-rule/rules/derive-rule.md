# Rule 1 - 目標步驟與展開模式必須明確

- 目標步驟必須以 Phase 編號與步驟編號唯一指定。
- 目標步驟內文含有用來判斷產出是否合格的判準時，必須使用抽取模式。
- 使用者要求為目標步驟補充原本沒有的規則時，必須使用新增模式。
- 同一個目標步驟同時符合兩種模式時，展開方案必須同時包含兩種模式，並標明每條候選 Rule 的來源模式。
- 目標步驟內文只屬於本步驟、且只有一項的執行條件，可以保留在步驟內文，不抽取；步驟內文的允許範圍參見 `skill-form-sop` 的 `rules/SOP-rule.md` Rule 4。

## Example

- 每列都能由目標步驟的現況判斷模式，且單一的執行條件被保留。

| 目標步驟內文 | 使用者需求 | 展開模式 |
| ------------ | ---------- | -------- |
| `WRITE` 產生錯誤訊息，訊息必須指出欄位名稱並提供修正方式。 | 整理這一步的規則 | 抽取 |
| `WRITE` 依已載入的錯誤訊息檢查清單產生錯誤訊息。 | 錯誤訊息還要附上 error code | 新增 |
| `WRITE` 產生錯誤訊息，訊息必須指出欄位名稱。 | 另外加上 error code 規則 | 抽取與新增 |
| `READ` 修改既有檔案時，讀取目標檔案。 | 整理這一步的規則 | 不展開：只有單一執行條件 |

# Rule 2 - 抽取必須保留原有語意

- 目標步驟中每一項被抽取的判準，必須對應到至少一條候選 Rule 的條列說明。
- 抽取不得新增原步驟沒有的要求，也不得刪減或放寬原有要求。
- 原文強度不明確（例如「注意」、「盡量」）時，必須轉換為固定強度用詞，並在展開方案中標示轉換前後的用詞；固定強度用詞參見 `skill-form-rule` 的 `rules/RuleFile-rule.md` Rule 7。
- 抽取後，目標步驟必須改為依載入結果名稱執行，不得殘留已抽取的判準。

## Example

- 原步驟的兩項判準各對應一條說明，「盡量」被轉換為「應」並標示，改寫後步驟只引用檢查清單。

改寫前：

```markdown
3. `WRITE` 產生錯誤訊息，訊息必須指出欄位名稱，並盡量提供修正方式。
```

候選 Rule：

```markdown
# Rule 1 - 錯誤訊息必須指出失敗位置與修正方式

- 錯誤訊息必須指出失敗的欄位名稱。
- 錯誤訊息應提供修正方式。（原文「盡量」轉換為「應」）
```

改寫後：

```markdown
3. `READ` 產生錯誤訊息時，讀取 `rules/error-message-rule.md` 的所有 Rule，建立錯誤訊息檢查清單。
4. `WRITE` 依已載入的錯誤訊息檢查清單產生錯誤訊息。
```

# Rule 3 - 候選 Rule 必須歸屬到單一主題的 RuleFile

- 候選 Rule 與目標 skill 既有 RuleFile 的主題相同時，必須追加到該 RuleFile。
- 沒有主題相同的既有 RuleFile 時，必須新建 RuleFile。
- 候選 Rule 涉及多個主題時，必須依主題拆分到不同 RuleFile。
- 候選 Rule 不得重複既有 RuleFile 已有的要求。
- 目標 RuleFile 已由目標步驟所在 Phase 中、位於目標步驟之前的 `READ` 步驟載入時，必須沿用該載入結果名稱，不得新增重複的載入步驟。

## Example

### Example 1

- 錯誤訊息 Rule 與既有 `error-message-rule.md` 同主題而追加；log 格式屬於不同主題而新建。

| 候選 Rule | 既有 RuleFile | 歸屬 |
| --------- | ------------- | ---- |
| 錯誤訊息必須附上 error code | `rules/error-message-rule.md` | 追加到 `rules/error-message-rule.md` |
| Log 必須包含 request ID | 無同主題檔案 | 新建 `rules/log-rule.md` |

### Example 2

- 步驟 3 已載入錯誤訊息檢查清單，新增的 Rule 追加到同一檔案後，步驟 5 沿用既有名稱，不另加載入步驟。

```markdown
3. `READ` 產生錯誤訊息時，讀取 `rules/error-message-rule.md` 的所有 Rule，建立錯誤訊息檢查清單。
4. `WRITE` 依已載入的錯誤訊息檢查清單產生錯誤訊息。
5. `CHECK` 逐條驗證錯誤訊息檢查清單。
```

# Rule 4 - 展開方案必須完整列出變更

- 展開方案必須包含下表所有欄位，供使用者在寫入前確認。
- 抽取模式的展開方案必須列出原步驟判準與候選 Rule 的對照。
- 展開方案不得包含目標 RuleFile 與目標 `SKILL.md` 以外的檔案變更。

| 欄位 | 內容 |
| ---- | ---- |
| 目標步驟 | Phase 編號、步驟編號與原步驟內文 |
| 展開模式 | 抽取、新增，或兩者 |
| 候選 Rule | 每條 Rule 的標題、條列說明與來源模式 |
| 目標 RuleFile | 檔案路徑，並標明追加或新建 |
| 載入步驟 | 新增 `READ` 步驟的位置與載入結果名稱，或沿用的既有載入結果名稱 |
| 改寫後步驟 | 目標步驟改寫後的內文；新增模式且內文不變時標明不變 |

## Example

- 方案逐欄列出變更，並附上抽取對照，使用者可以直接核對。

展開方案：

- 目標步驟：Phase 2 步驟 3，`WRITE` 產生錯誤訊息，訊息必須指出欄位名稱，並盡量提供修正方式。
- 展開模式：抽取。
- 候選 Rule：Rule 1 - 錯誤訊息必須指出失敗位置與修正方式（抽取）。
- 目標 RuleFile：`rules/error-message-rule.md`（新建）。
- 載入步驟：在 Phase 2 步驟 3 之前新增 `READ` 步驟，建立錯誤訊息檢查清單。
- 改寫後步驟：`WRITE` 依已載入的錯誤訊息檢查清單產生錯誤訊息。

抽取對照：

| 原步驟判準 | 候選 Rule 說明 |
| ---------- | -------------- |
| 必須指出欄位名稱 | 錯誤訊息必須指出失敗的欄位名稱。 |
| 盡量提供修正方式 | 錯誤訊息應提供修正方式。（「盡量」轉換為「應」） |
