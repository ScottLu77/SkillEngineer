## Rule 1 -- 判定清單條目格式規則

- MUST: 每筆條目寫成 `<位置>: 「<原句>」 -> <判定>`。
- MUST: <位置> 寫成 `Phase N 第 M 步`; 不在步驟內寫 `Phase N (步驟外)`; 不在任何 Phase 內寫 `(Phase 外)`。
- MUST: <原句> 一字不改地摘自 SKILL.md, 可只取句子的一部分。
- MUST: 內嵌範例的 <原句> 寫成 `L<起始行>-<結束行> 範例`。
- MUST: <判定> 寫成 `流程: <理由>`、`指引: <理由>` 或 `規則候選 (<產出物> / <部分>): MUST: <改寫後的要求>` 之一。
- MUST: <產出物> 寫成規則檔檔名 `<產出物>-rule.md` 中的名稱; <部分> 寫成該產出物的一個組成部分名稱。

### Good example

位置、原句與判定都依格式寫成

```
Phase 1 第 2 步: 「每個步驟格式為 `**動詞短語**: 說明`」 -> 規則候選 (draft-sop / 步驟): MUST: 每個步驟格式為 `**動詞短語**: 說明`。
Phase 1 第 3 步: 「若有修改, 則回第 2 步」 -> 流程: 換掉後步驟沒有去向
Phase 2 第 1 步: 「L19-21 範例」 -> 規則候選 (sop / 步驟): MUST: 步驟依 `<步驟編號>. <動作詞> <操作內容>, <去向>。` 的順序寫成。
```

### Bad example

第一筆沒有位置且判定不在三種之內; 第二筆的判定沒有理由; 第三筆的規則候選沒寫產出物與部分

```
「格式要用動詞短語」 -> 是規則
Phase 1 第 3 步: 「若有修改, 則回第 2 步」 -> 流程
Phase 2 第 1 步: 「步驟編號從 1 開始」 -> 規則候選: MUST: <步驟編號> 在每個 Phase 內從 1 開始連續編號。
```


## Rule 2 -- 判定規則

- MUST: 將 <原句> 換成「參考本 skill 的 `rules/<產出物>-rule.md`」後, 所在步驟仍缺少動作詞、讀寫或參考的檔案、或去向時, 判定為 `流程`。
- MUST: 不屬 `流程`、且 <原句> 約束產出物的格式、編號、命名、用詞或範例時, 判定為 `規則候選`。
- MUST: <改寫後的要求> 只管一個對象 (同一個對象的多個條件可以合寫), 且兩位審查員各自檢查會得到相同判定。
- MUST: 其餘條目 (含改寫不出上一條要求的) 判定為 `指引`。

### Good example

換掉後沒有去向判為流程, 約束編號與整步都在講格式的句子判為規則候選, 需主觀判斷判為指引

```
Phase 1 第 3 步: 「若有修改, 則回第 2 步」 -> 流程: 換掉後步驟沒有去向
Phase 2 第 1 步: 「步驟編號從 1 開始」 -> 規則候選 (sop / 步驟): MUST: <步驟編號> 在每個 Phase 內從 1 開始連續編號。
Phase 2 第 2 步: 「Body 每行最多 72 字元」 -> 規則候選 (commit-message / Body): MUST: Body 每行不超過 72 個字元。
Phase 1 第 3 步: 「問使用者時先給推薦選項」 -> 指引: 推薦是否恰當需主觀判斷
```

### Bad example

第一筆換掉後步驟沒有去向, 應判為流程; 第二筆改寫出的 MUST 需主觀判斷, 應判為指引

```
Phase 1 第 3 步: 「若有修改, 則回第 2 步」 -> 規則候選 (sop / 步驟): MUST: 有修改時回第 2 步。
Phase 1 第 3 步: 「問使用者時先給推薦選項」 -> 規則候選 (question / 選項): MUST: 選項要給得恰當。
```


## Rule 3 -- 掃描範圍規則

- MUST: 本 skill 的 `scripts/find-signal-sentences.sh` 輸出的每一行都至少有一筆條目。
- MUST: 不在腳本輸出中、但依 Rule 2 判定為 `規則候選` 的句子也列為條目。
- MUST: frontmatter 中的句子不列為條目。

### Good example

腳本輸出的「只能」句已列入, 腳本沒抓到的標題要求也已列入, frontmatter 的「必須」未列入

```
--- SKILL.md ---
description: 建立 demo 時必須使用此 skill。
### Phase 1 -- 撰寫草稿
注意: 動作詞只能用 READ、WRITE、THINK。
1. WRITE 寫出草稿, 標題以「草稿:」開頭, 到下一步。

--- 判定清單 ---
Phase 1 (步驟外): 「動作詞只能用 READ、WRITE、THINK」 -> 規則候選 (draft / 動作詞): MUST: <動作詞> 只能是 READ、WRITE、THINK 之一。
Phase 1 第 1 步: 「標題以「草稿:」開頭」 -> 規則候選 (draft / 標題): MUST: 標題以「草稿:」開頭。
```

### Bad example

同一份 SKILL.md, 漏列腳本輸出的「只能」句, 且列入了 frontmatter 的句子

```
--- 判定清單 ---
(Phase 外): 「建立 demo 時必須使用此 skill」 -> 流程: 觸發條件
Phase 1 第 1 步: 「標題以「草稿:」開頭」 -> 規則候選 (draft / 標題): MUST: 標題以「草稿:」開頭。
```
