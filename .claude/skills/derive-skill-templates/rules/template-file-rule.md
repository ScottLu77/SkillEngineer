## Rule 1 -- 範本檔結構規則

- MUST: 範本的段落結構與產出物一一對應, 每次都相同的固定文字原樣寫出。
- MUST: 每次不同的內容以 `<說明>` 佔位符取代, 不寫範例值。
- MUST: 可重複或可省略的區塊, 以 HTML 註解 `<!-- -->` 寫明重複或省略的條件。
- MUST: 佔位符與 HTML 註解以外的文字都是固定文字, 不寫給填寫者看的說明。

### Good example

固定文字原樣寫出、需填寫部份用佔位符、可省略區塊用註解說明條件、沒有多餘說明文字

```
<type>: <摘要>

<說明這次變更為什麼需要>

<!-- 有關聯的 issue 時, 加上下一行 -->
Refs: <issue 編號>
```

### Bad example

需填寫部份寫成範例值、可省略區塊沒有註解說明條件、給填寫者看的說明寫在固定文字區

```
feat: add retry

說明一下為什麼要改。

Refs: #123
(沒有 issue 可以不寫 Refs)
```

## Rule 2 -- 佔位符寫作規則

- MUST: 格式為 `<說明>`, 說明寫明要填入什麼內容。
- MUST: 一個佔位符只填入一個值。
- MUST: 填入內容有限制時, 限制寫在佔位符內 ex. `<與目錄名稱相同的 kebab-case 名稱>`。
- MUST: 不寫模糊用語 ex.「適當」、「視情況」、「必要時」。

### Good example

每個佔位符只填一個值, 限制寫在佔位符內, 沒有模糊用語

```
<feat、fix、docs 三選一的 type>: <以動詞開頭且不超過 50 個字元的摘要>
```

### Bad example

第 1 個佔位符塞了兩個值且沒寫限制, 第 2 個佔位符用了模糊用語

```
<type 與摘要>: <適當的內容>
```
